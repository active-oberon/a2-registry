RealConversions.PeekNext

Procedure used in ScanReal for peeking the next character from the input character stream.

An example:

PROCEDURE Next(): CHAR; BEGIN INC(streamPos); ( preincrement the stream position ) IF streamPos < streamLength THEN RETURN stream(streamPos); ELSE RETURN 0X; END; END Next;

Syntax

TYPE PeekNext* =PROCEDURE{DELEGATE} (): CHAR

RealConversions.ScanReal

Scan a floating-point number. EBNF Real = [{' '}] ['+'

'-'] [Digit {Digit}] '.' Digit {Digit} ['d''D'e''E'' ['+''-'] Digit {Digit}].

ch : first peek from the input character stream next : a procedure to peek the next character r : scanning result

Returns TRUE in case of a valid conversion. The result value r remains unchanged in case of an error.

Syntax

PROCEDURE ScanReal* (ch: CHAR; next: PeekNext; VAR r: FLOAT64): BOOLEAN

RealConversions.StringToReal

Convert a string to a floating-point number. EBNF Real = [{' '}] ['+'

'-'] [Digit {Digit}] '.' Digit {Digit} ['d''D'e''E'' ['+''-'] Digit {Digit}] [{' '}].

s : input null-terminated string; absence of the terminating null can cause an index out of range exception r : conversion result

Returns TRUE in case of a valid conversion. The result value r remains unchanged in case of an error.

Syntax

RealConversions.RealToDecimal

The digits of a binary64, correctly rounded to `significant` of them.

value = <digits as an integer> * 10^exponent, with exactly `significant` digits and no sign; a zero answers a string of zeros and exponent 0. Seventeen digits is what a binary64 needs to be read back as itself, and RealToString stops at sixteen -- which is why a symbol file could not carry a constant unchanged.

The value is turned into its exact decimal first (a binary64 has at most 767 digits of one) and only then rounded, once, ties to even.

Syntax

PROCEDURE RealToDecimal* (value: FLOAT64; significant: SIGNED32; VAR digits: ARRAY OF CHAR; VAR exponent: SIGNED32)

RealConversions.DecimalToReal

Convert a decimal literal to binary64, correctly rounded.

digits : the significant decimal digits, 0X terminated, no sign and no point exponent : the power of ten they are to be multiplied by rest : the digits were cut short by the caller and what it dropped was not all zeros

Returns FALSE when the value does not fit binary64; r is left alone then. A value too small to represent is zero and a valid conversion, the way IEEE 754 underflow is.

Syntax

PROCEDURE DecimalToReal* (CONST digits: ARRAY OF CHAR; exponent: SIGNED32; rest: BOOLEAN; VAR r: FLOAT64): BOOLEAN
