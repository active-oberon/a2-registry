DAP.Ready

Ready is called by the launcher once the program's module is loaded and before the program starts the code exists, so this is the one moment a breakpoint can be written into it.

Syntax

TYPE Ready* =PROCEDURE{DELEGATE}

DAP.Launcher

Launcher compiles the program and runs it, returning when it has ended. `ob dap` passes the one that knows about search paths and --debug; a test passes its own. Whatever the program writes goes to `out`, never to this process's stdout, which carries the protocol.

Syntax

TYPE Launcher* =PROCEDURE{DELEGATE} (CONST program, procedure: ARRAY OF CHAR; out: Streams.Writer; ready: Ready; VAR message: ARRAY OF CHAR): BOOLEAN

DAP.Stopped

Stopped is how a Core says the program stands still: why, and the frame it stands on. `ob dap` turns it into a stopped event; PET moves the caret there.

Syntax

TYPE Stopped* =PROCEDURE{DELEGATE} (CONST why, description: ARRAY OF CHAR)

DAP.Core

Core is the debugger with no protocol in it: the two hooks A2's trap handler calls, the instructions planted in the program's code, and the stack of the activity being held. What to do when it stops is the owner's business, said once through Stopped -- `ob dap` writes a stopped event, PET moves the caret. Everything a driver has to read afterwards is a read-only field, because a getter per field would be longer than the object.

DAP.Core.Forget

Forget drops every line asked for; Want adds one back. Together they are setBreakpoints.

Syntax

PROCEDURE Forget*

DAP.Core.Arm

Arm resolves every line into an address and writes the breakpoints in. Called once the module carrying them is loaded, and again whenever the lines change.

Syntax

PROCEDURE Arm*

DAP.Report

Report writes where the program stands, as text: one line per frame of the program with the file and line it is in, and under the innermost one the parameters and locals it holds. A driver with no protocol -- PET -- needs exactly this and none of the JSON.

It stops at the first frame the line table knows nothing about, and that is not a shortcoming below the program's own frames is the machinery that started it (Commands.Runner, Objects.BodyStarter), which was not compiled with --debug and has no business in a report about the program. Reflection.StackTraceBack, which a trap dump is made of, prints all of it and by byte offset rather than by line -- right for a post-mortem on the console, wrong for an editor that has just put the caret on the line.

Syntax

PROCEDURE Report* (core: Core; w: Streams.Writer)

DAP.Serve

Serve one debug session over a context, which is how `ob dap` and the tests both drive it: the requests come in on its input, the responses and events go out on its output.

Syntax

PROCEDURE Serve* (context: Commands.Context; launcher: Launcher)
