FoxDisassembler.FindPC

Which code section an address is in, and how far into it -- what turns the number in a trap report into a name and an offset. `FoxDisassembler.FindPC <log> <address>`.

Four things were wrong with twenty lines:

- `found` was assigned only inside the loop and dereferenced whatever happened, so an address below every code section was an access violation. In a command whose whole subject is an address somebody read off a trap report. - the nearest section below the address was found with a strict comparison, so an address exactly at a section's start belonged to the section before it -- and the first instruction of a procedure is the address one looks up most. - the refusal named the file after the extension had been added to it: a caller who asked about `nosuch.log` was told about `nosuch.log.log`. - a command line it could not read was answered with silence, which reads like an answer.
