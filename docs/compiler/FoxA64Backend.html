FoxA64Backend.BackendA64.CanPassInRegister

whether a whole aggregate may travel in a register rather than by address

AAPCS64 does have a rule for this -- a homogeneous floating-point aggregate of up to four members goes in consecutive V registers -- but A2 passes records and arrays by address anyway, so nothing reaches here that the rule would apply to. Left FALSE until a case turns up that needs it; saying TRUE without a code generator behind it would only produce wrong code later.

Syntax

PROCEDURE CanPassInRegister* (type: SyntaxTree.Type): BOOLEAN

FoxA64Backend.BackendA64.GetParameterRegister

the AAPCS64 argument allocation, as far as the intermediate code models it

Two independent counters, x0..x7 for everything integer or pointer shaped and v0..v7 for everything floating point -- the same shape as the SysV rule on AMD64 and not the WINAPI one, where a float consumes an integer slot too.

The counters only ever increase, which is the other half of the rule: once an argument of a class has gone to the stack, every later argument of that class goes to the stack as well, even if a register of that class fell free. AAPCS64 says this explicitly (NGRN and NSRN are set to 8 rather than left alone), and the shared caller and prologue loops in FoxIntermediateBackend do it by construction.
