Frames.Screen

A screen, as Oberon divides one: vertical tracks side by side, and in each track the frames stacked one above the other. Tiled throughout -- no frame is ever hidden behind another, which is the whole reason the model needs no window manager.

A screen with one frame in each of two tracks is two columns; a screen with two frames in one track is two rows; and the arrangement most programs want -- a narrow list beside a pair of frames -- is what neither of those alone could say.

Frames.Screen.Draw

Draw the frames over what is already there. Nothing is cleared first: every frame paints every cell it owns, borders and blanks included, so clearing would only mean the screen spends a moment empty -- which is what flicker is.

Syntax

Frames.Execute

Any line is a command: the first word names it, in the form Module.Procedure, and the rest are its arguments. What it writes goes into `into`, line by line, which is how a log in one frame is filled by a command run from another -- and, being a text like any other, is itself a list of lines somebody can run again. FALSE when there is no such command; the reason is appended to `into` either way.

Syntax

PROCEDURE Execute* (CONST line: ARRAY OF CHAR; into: Text): BOOLEAN
